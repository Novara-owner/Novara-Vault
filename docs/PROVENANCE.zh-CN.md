## 这一页是什么

这是「**一个 Novara 版本是怎么被生产出来的**」的单一出处：流水线跑了什么、每个版本附带什么、构建被钉到什么程度，以及同样重要的——我们**不**声称什么。[VERIFYING.zh-CN.md](VERIFYING.zh-CN.md) 回答「**怎么核验**一次下载」；本页回答「你**拿什么去核验**」。

## 流水线

版本由本仓库的 CI 工作流（[`.github/workflows/ci.yml`](../.github/workflows/ci.yml)）在版本 tag 上产出。仍有一步在它之外：Windows 安装包在发布机上打包（见下）。

| 阶段 | 做什么 | 能否拦住发布？ |
|---|---|---|
| 构建与测试 | 以锁定模式还原依赖、以 Release 构建核心与三个服务端工程、跑全量单元测试，并对测试跑一次 80% 行覆盖率门禁 | 能 |
| 依赖与许可证审计 | 扫描全部工程的已知漏洞并**在任何 Critical 公告上直接失败**；记录 High 待人工复核；校对已提交的第三方许可证清单 | 能（Critical） |
| 桌面构建 | 构建 WinUI 桌面应用 | 能 |
| 发布产物 | 发布自包含的同步服务端可执行文件 | 能 |
| 签名 | **10.0 起**对容器镜像与安装包签名（见下） | 能 |

Windows 安装包由**同一份源码**在发布机上打出、作为附件挂到 Release 页，随后由 CI 作业完成签名——签名由流水线产出，不靠手工。**依[《代码签名政策》](CODE_SIGNING_POLICY.zh-CN.md)签名的安装包，由 CI 工作流从打了 tag 的源码构建。**

## 每个版本附带什么

| 附件 | 钉住的是什么 |
|---|---|
| `Novara_Setup_x.y.z.exe` | Windows 安装包 |
| `SHA256SUMS` | 安装包的 SHA-256 |
| `IMAGES.txt` | 容器镜像的精确 digest——GHCR 与 Docker Hub 是同一个 digest |
| `novara-sync-x.y.z.spdx.json` | 软件物料清单（SPDX，Syft 生成） |
| `signature.bundle` | **10.0 起**安装包的 Sigstore 签名包 |

## 构建被钉到什么程度（10.0 及以后）

- **SDK 版本**在 `global.json` 里精确钉死并**关闭 roll-forward**，编译器与 SDK 自带的构建工具无法静默漂移。
- **依赖**由入库的 NuGet 锁文件钉住，且 CI 以**锁定模式**还原：一旦解析结果与锁文件对不上，还原**直接失败**，而不是悄悄换成别的版本。
- **源码路径**在发布构建里被映射到中性根目录，因此出厂二进制不携带构建机的目录结构。
- **发布产物在 Level 1 上可复现**——同一冻结提交、同一环境，产出逐字节相同。发布流程要求在发布前**构建两次并逐文件比对**、**编译安装包两次并比对哈希**。

## 我们**不**声称什么

我们宁可把边界说清，也不愿让你以为我们做到了做不到的事。

- **不能从本公开仓库复现。** 本仓库是**发布快照**：发布前会剥掉注释、并移除少量与机器绑定的构建设置。剥注释不改变编译产物，但净化同时改写了**会进安装包**的文件（辅助用的 `.cmd` 脚本），因此从公开树构建**无法**复现已发布的字节。复现的基准是**我们开发仓里的那个冻结提交**，且每个版本都会记录其工具链版本。
- **不能跨机器复现。** Level 1 的含义是**同一环境**。另一套 Visual Studio / Windows SDK 会带来不同的 XAML 与资源编译器，产物随之改变。我们宁可如实记录工具链，也不假装它无关紧要。
- **安装包尚未做 Authenticode 签名**，首次运行时 SmartScreen 仍可能提示——见 [VERIFYING.zh-CN.md](VERIFYING.zh-CN.md)。
- **出厂二进制包含调试信息。** 我们随 exe 一起提供 `.pdb`，这样你机器上的崩溃报告才能指出**确切的源码行号**。发布构建已把源码路径映射到中性根目录，但调试元数据里仍记录着本次构建自身的文件布局。
- **没有第三方独立审计。** OpenSSF Scorecard 是自动化评分，威胁模型是我们自己写的。二者都不是第三方安全审计。

## 签名（10.0 及以后）

容器镜像与安装包以 [Sigstore](https://www.sigstore.dev/) 的**无密钥**方式签名，由产出该版本的**同一个工作流**完成。没有可被窃取的长期签名私钥：每份签名都附带一张短期证书，把仓库、工作流文件与 tag 钉死，并记入公开的透明度日志。校验命令见 [VERIFYING.zh-CN.md](VERIFYING.zh-CN.md)。
