## 1. 如何读这份文档

Novara 是一个运行在**你自己的机器**上的本地优先个人数据控制层。对桌面应用而言，一份有用的威胁模型不可能是「我们防御了什么」的清单——它必须说清**每条边界在哪里、以及边界成立需要什么前提**。因此本页直白地陈述五件事：保护资产、攻击者类别、我们依赖但并不掌控的安全假设、我们**刻意不**保护的部分，以及实现每条边界的具体缓解措施。

由此有两个推论，且都是刻意的：本页一切内容都假设**你是这台机器上唯一拥有合法账户的人**；并且，本页不保护数据免受**已经以你的权限运行**的软件的侵害。

## 2. 保护资产

值得保护的东西，以及它们以什么形态存在：

- **数据库（`data.novadb`）**——日记、备忘、计划与文档，集中在 `%LocalAppData%\Novara` 下的单个文件里。它的保护程度取决于隐私锁是否开启：**加密默认关闭**，明文库仅由你的 Windows 账户权限守护。
- **锁屏密码与派生密钥**——密码永不落盘。`security.dat` 只保存一个带版本号、带盐的 PBKDF2-SHA256 哈希，用于锁屏校验；它**不是**加密密钥，也无法解密数据库。
- **MCP 凭据**——按用户签发的 Agent token、每个客户端的授权记录，以及各客户端自己的权限矩阵。
- **同步机密**——空间密钥（在首台设备上生成，从不外传）、一次性配对密钥，以及各设备自己的 token。
- **导出副本**——快照、加密备份，以及明文 `.novabak` 导出（只带完整性校验：防损坏，不防篡改）。
- **本地日志与历史**——审计日志、崩溃日志（已脱敏），以及回收站与滚动备份当前持有的内容。
- **你选择存进 Novara 的凭据**——备忘区正是 API 密钥会落脚的地方，因此在整套 MCP 模型里，备忘区被当作最敏感的分区对待。

## 3. 攻击者

共七类。每一类都给出「必须成立的边界」与「边界失效的条件」。

- **A1 —— 同一台机器上的另一个人。** 共用电脑、借用笔记本、站在身后看屏幕的人。*边界：* 隐私锁 + 你的 Windows 账户权限。*成立前提：* 库已加密**且**应用处于锁定状态。*失效条件：* 隐私锁未开——此时磁盘上是明文 JSON；或应用已解锁且无人看管。锁屏在窗口失去焦点时会清空输入框；连续 5 次输错密码后，解锁会被封锁 30 分钟。
- **A2 —— 以你的身份运行的恶意软件，或已被攻陷的 Windows 账户。** 键盘记录、屏幕录制、远程木马。*边界：* 结构上不存在。以你的权限运行的代码能读到应用所读的明文、在你输入时截获密码、截取窗口画面，并在库解锁期间从进程内存中取出密钥。
- **A3 —— 持有你数据副本的离线攻击者。** 磁盘镜像、被窃取的备份、被传播得过广的快照文件、退役的硬盘。*边界：* AES-256-GCM + 每用户随机盐、300 万次迭代的 PBKDF2-SHA256。*成立前提：* 该副本是加密容器**且**密码足够强。*失效条件：* 副本是明文库或明文导出，或密码可被猜出——KDF 抬高的是每一次猜测的成本，它并不能让弱密码变安全。
- **A4 —— 同步路径上的网络攻击者。** *边界：* 密文本身与传输层。服务端只保存一条带版本的密文块加一个小型明文信封（容器 / 加密 / 同步三个版本号、载荷所基于的基线版本、设备 id 与时间戳），且不持有任何密钥；协议假定 HTTPS，随包服务端默认只绑定回环地址。*注意：* 同步服务端确实在监听连接——它是你主动选择运行的组件，其部署（TLS 终结、是否暴露到公网）由你负责做对。
- **A5 —— 你批准过的 AI 客户端，以及其供应商在上游所做的一切。** *边界：* 解锁门禁、按客户端授权、权限矩阵、字段脱敏、删除总闸与审计日志。*失效条件：* 一个被授予宽权限的客户端把它合法读到的内容转发给云端服务——Novara 能控制客户端在本地可读可写什么，但控制不了其供应商如何处理这些数据。
- **A6 —— 攻击我们分发渠道的人。** 发布产物、容器镜像、更新清单、我们的依赖。*边界（10.0 起，签名自 10.1 起）：* 产物产出前 CI 必须全绿；每个版本都带 `SHA256SUMS`；镜像 digest 钉在 `IMAGES.txt` 里；发布 SBOM；安装包与镜像自 10.1 起带无密钥 [Sigstore](https://www.sigstore.dev/) 签名，签名把产出它的工作流与 tag 钉死。见[校验你的下载](VERIFYING.zh-CN.md)。
- **A7 —— 物理接触，或操作系统之下的任何层面。** 引导级篡改、被攻陷的固件或虚拟机监控程序、对知道密码的人施加胁迫。**不在范围内**——见第 5 节。

## 4. 安全假设

设计依赖、但设计本身并不保证的前提：

- **你的操作系统与账户未被攻陷。** 上述每条边界都是「静止态」或「进程内」的边界；对已经以你的身份运行的攻击者，它们一条都不成立（A2）。
- **你会选择足够强的密码。** 300 万次迭代的 KDF 抬高每一次猜测的成本，但救不了一个弱密码。设计上没有密码找回。
- **你自己的地盘加密到什么程度，由你决定。** 如果磁盘未由操作系统加密，那么绕开应用拿到的 Novara 文件副本，其受保护程度就等同于这些文件本身。
- **同步路径上的传输安全由你的部署负责。** Novara 假定 HTTPS，并推荐用反代做 TLS 终结；把服务端跑在明文 HTTP 上或暴露到公网，是一个有后果的部署选择。
- **Windows Hello 是便利门禁，不是密码学绑定。** 它只控制「从操作系统凭据保管库取回你的密码」这一步；加密链路本身不变，它缺失或失败时永远回落到密码。
- **你的 AI 客户端在边界之外的行为，由你与它的约定管辖。** 见 A5。
- **你的备份与导出副本，其保管方式与原件同等重要。** 快照或备份受保护的程度 = 它的密码 + 你把它放在哪里。
- **你的时钟大体可信**——只有一个刻意例外：登录锁定使用单调时钟，因此把系统时钟往回调并不能缩短封锁时间。

## 5. 非目标

下列各项我们**不**声称能防护。这些是刻意的立场，不是疏漏。

- **已解锁的会话**——应用解锁运行期间，能操作你机器的人能看到你所看到的内容。
- **内存提取**——库解锁期间，密钥存在于进程内存中。
- **丢失或遗忘密码**——没有找回路径，没有后门，也没有远程解锁。
- **胁迫与威逼**——没有胁迫密码，也没有似是而非的否认模式。
- **多用户隔离**——这是单用户桌面应用，不是多租户系统。
- **安全擦除**——删除会把数据移出数据库并清空回收站，但我们对存储设备层面的残留不做任何承诺。
- **你自托管服务端的可用性**——针对它发起的拒绝服务，或它本身的损失，都在模型之外。
- **已被攻陷的操作系统、固件或虚拟机监控程序**，以及操作系统之下的物理层攻击。
- **任何「官方云」才需要防的事。** 我们并不运营云：没有账号、没有遥测、没有分析，也没有任何能读到你的数据的服务端——这是承诺（见安全说明第 9 节）。
- **你的网络元数据**——Novara 不会向你的网络运营者隐藏你所触发的连接的存在。这些出站路径都列在应用内的网络活动面板里。

## 6. 缓解措施

每项机制、它真正的作用，以及它**不**覆盖的部分：

| 缓解措施 | 防护对象 | 不防护的对象 |
|---|---|---|
| 带版本头的 AES-256-GCM（12 字节 nonce、16 字节 tag） | 加密文件被静默篡改与未经授权读取（A1、A3） | 明文库；已解锁的会话 |
| 每用户随机盐、300 万次迭代的 PBKDF2-SHA256 | 离线猜测的成本（A3） | 弱密码；机器上软件的直接窥视 |
| 封锁：连续 5 次失败封 30 分钟，状态落在 `lockout.dat`，用单调时钟 | 在锁屏界面上试密码（A1） | 对已复制文件发起的离线攻击 |
| 原子写入 + `Flush(true)`、串行化保存队列、单实例互斥与独占文件锁 | 损坏与并发覆盖 | 保密性——这是一条数据完整性措施 |
| 回收站与滚动本地备份 | 误删 | 对机器本身的蓄意破坏 |
| `.novaenc` v4 容器、每次导出强制密码门、封包前剥离凭据 | 明文离开本机；快照外泄（A3） | 弱导出密码；密码可猜的被复制文件 |
| 服务端只存密文、密钥分离、设备 token 仅存 SHA-256 且常时比较并对失败限流 | 好奇或被攻陷的服务端（A4） | 未做 TLS 的部署；服务端自身的可用性 |
| 浏览器阅读器只在 JS 内存中持有明文，不向浏览器持久化任何内容 | 数据滞留在共用浏览器上 | 已被攻陷的浏览器或扩展 |
| MCP 默认关闭、解锁门禁、按客户端授权、权限矩阵、删除总闸、字段脱敏、本地审计日志 | 权限过宽或好奇的 Agent 客户端（A5） | 供应商如何处理客户端合法读到的数据 |
| 导入与编辑器按严格白名单净化（AngleSharp）、不对不可信输入求值 | 通过导入内容进行的注入 | 在已被攻陷的渲染器内渲染的恶意内容 |
| 桌面端不开放监听端口、出站只走你主动触发的路径、便签宿主仅本地通信 | 远程攻击面（A4） | 你自己关于「要连什么」的决定 |
| CI 门禁、`SHA256SUMS`、镜像 digest 钉值、SBOM、无密钥 Sigstore 签名（10.1 起） | 分发渠道被篡改（A6） | 平台本身或签名基础设施被攻陷 |

## 7. 报告

发现本页与实际产品之间有出入？那属于安全问题——请走 [SECURITY.zh-CN.md](../SECURITY.zh-CN.md) 第 2 节的私密渠道。一份与软件自相矛盾的威胁模型本身就是缺陷，我们宁可改这一页，也不去为它辩护。
