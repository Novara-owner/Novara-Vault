# Novara 互联同步 · 部署指南

> 面向对象：想在自己的服务器上跑 Novara 同步、让手机也能查看与编辑数据的个人用户。
> 本文是**内容稿**（供网页设计使用），不是开发者文档；技术细节以仓库内 `deploy/README.md`（部署与验收）与 `deploy/SECURITY.md`（安全基线）为准。
> 适用范围：**Novara 8.0.0**。文中每条路径都在仓库里对应一份可照抄的配置样例。

---

## 0. 一句话先说明白

互联同步 = **你自己的一台服务器** + **只有你能解开的密文**。

Novara 官方**不提供云服务**，也不代表任何托管方。你的数据在离开电脑之前就已经加密，服务器全程只搬运密文——它不知道你存了什么，也打不开。

如果你不需要跨设备，**完全可以不装**：Novara 的全部本地功能都不依赖它。

---

## 1. 先选对工具：安全快照，还是互联同步？

Novara 有两套"把数据带出去"的能力，解决的问题不一样：

| | **安全快照** | **互联同步** |
|---|---|---|
| 一句话 | 导出一个加密的单文件网页 | 数据在设备之间双向同步 |
| 需要服务器吗 | **不需要**（丢到任意静态托管即可） | **需要**，你自己搭 |
| 只读还是可编辑 | **永远只读**（静态文件） | 手机端**可查看、可编辑** |
| 数据新鲜度 | 导出那一刻的快照 | 每次同步都是最新的 |
| 适合谁 | 只想在手机上翻一下密码、又不愿折腾服务器 | 想让手机成为真正可用的第二个入口 |

- 只要"看一眼" → 用**安全快照**就够了，它简单得多。
- 要"改一条备忘、勾一个待办、补一段记录" → 需要**互联同步**。

本文只讲互联同步。

## 2. 开始之前

### 2.1 你需要准备

| # | 东西 | 说明 |
|---|---|---|
| 1 | **一台一直开着的电脑** | 家里/办公室的 Windows 电脑、长期在线的机器都行。它关机时手机连不上（但这不影响你电脑上继续正常用 Novara） |
| 2 | **NovaraSync 服务端程序** | 已随 Novara 安装包一并提供（安装目录下的 `Sync\` 文件夹），无需另行下载，也无需另装 .NET 运行时 |
| 3 | **一条"手机能访问到它"的通道** | 四选一，见第 3 节。公网访问推荐「域名 + 自动证书」，不想碰域名就用 Tailscale |
| 4 | **一台手机** | 任意现代浏览器（Chrome / Edge / Firefox / Safari 16.4+） |

### 2.2 你不需要准备

- ❌ 不需要域名（Tailscale / 局域网路径不需要）
- ❌ 不需要买云服务（用你自己已有的机器）
- ❌ 不需要 Docker（Docker 与 NAS 专用教程随**下个版本**提供）
- ❌ 不需要把密码告诉任何人，也不需要告诉服务器

### 2.3 一条硬要求：手机端必须走 HTTPS

浏览器的加密能力（`crypto.subtle`）只在**安全上下文**里提供。所以：

- `https://` 地址 → 正常
- `http://` 且非本机回环地址 → **浏览器不会提供加密能力**，页面会明确告诉你"当前浏览器不支持所需的加密能力"
- 自签证书**不被信任**时也一样（点"继续访问"也无效）——必须把证书装进手机并开启完全信任

反过来说：服务端自己也会拒绝明文凭据——**非 HTTPS 且非本机的 API 请求一律 403**，不会默默收下你的凭据。

## 3. 四条上线路径（按推荐顺序）

| 路径 | 适合 | 需要 | 难度 |
|---|---|---|---|
| **A. 域名 + 自动证书** | 有域名、想公网随时访问 | 一个域名（A 记录指向服务器） | ⭐⭐ 推荐 |
| **B. Tailscale** | 不想碰域名、只要自己的设备能访问 | 服务器与手机都装 Tailscale | ⭐ 隐私最好 |
| **C. Cloudflare 临时隧道** | 只想**临时验收**一下 | 无需域名 | ⭐ 但**验收完请立刻关掉** |
| **D. 局域网 + 自签证书** | 只在家里用 | 需把 CA 证书装进手机（iOS 还要手动开启完全信任） | ⭐⭐⭐ 最容易白做 |

> **不要**把服务端的明文端口直接暴露到网络上。服务端只应监听本机（`127.0.0.1`），由反代或隧道对外。

## 4. 完整步骤（以路径 A 为例）

### 第 1 步：建空间（一次性，只做一次）

**最省事的方式**：在安装目录的 `Sync\` 文件夹里**双击 `1-建空间.cmd`**，按提示做即可——它会自动把数据目录定到可写的位置，并打印下面这两样东西。脚本执行完就完成了本步，可直接跳到第 2 步。

**手动方式**（其它系统或想自己控制时）：打开命令行，进到 NovaraSync 所在目录，执行：

```bat
NovaraSync.exe space create --name my-space
```

无论哪种方式，命令都会打印**两样东西，且只打印这一次**：

```
space id          : <一串随机字符>
enrollment secret : <另一串随机字符>
```

- 这两样是"把设备接进这个空间"的凭据，**当场收好**。
- ⚠️ **建空间与服务端必须用同一个数据目录**（同一个工作目录，或同一个 `NOVARA_SYNC_DATA`）——否则凭据会落进另一个目录，服务端看不到这个空间，后面必然卡住。安装包自带的两个 `.cmd` 已经把这一点处理好了（都指向 `%LOCALAPPDATA%\Novara\Server\data`）。
- 空间密钥（真正的加密钥匙）**不在这里产生**——它由你第一台配对的电脑生成，服务器永远拿不到它。

### 第 2 步：启动服务端

**最省事的方式**：在同一个 `Sync\` 文件夹里**双击 `2-启动服务端.cmd`**，它会用与第 1 步相同的数据目录启动服务端。窗口关掉 = 服务端停止。

**手动方式**：

```bat
NovaraSync.exe --urls http://127.0.0.1:5180
```

- 只监听本机，**外面的网络直接访问不到**——这是有意的，对外访问一律走第 3 步的 HTTPS 通道。
- 想改数据目录/配额/保留份数等，见文末「附录 A 环境变量」。

### 第 3 步：配上 HTTPS 通道

**路径 A**：用 Caddy 做反代 + 自动申请证书（仓库内的 `deploy/Caddyfile` 可直接照抄）。把里面的 `novara.example.com` 换成你的域名，然后：

```bat
caddy run --config deploy\Caddyfile
```

两个关键点（Caddy 默认已满足，但换其它反代时要自己确认）：

1. 反代必须转发 **`X-Forwarded-Proto`** 与 **`X-Forwarded-Host`**——否则跳转会指向内网地址，手机打不开；
2. 若反代**不在同一台机器**上，还要把它的 IP 填进 `NOVARA_SYNC_TRUSTED_PROXIES`，否则服务端不信任它转发的头，会判定请求"不是 HTTPS"而返回 403。

**路径 B（Tailscale）**：服务器与手机都加入同一个 tailnet，用 Tailscale 提供的设备名/IP 访问即可，无需域名与证书。

**路径 C（Cloudflare 临时隧道）**：`cloudflared tunnel --url http://127.0.0.1:5180`，拿到一个临时域名。**仅用于验收，验收完立刻关掉。**

**路径 D（局域网 + 自签）**：自签证书必须被手机信任，否则页面不是安全上下文。iOS 还需在「设置 → 通用 → 关于本机 → 证书信任设置」里手动开启完全信任。

### 第 4 步：桌面端配对

打开 Novara → 汉堡菜单 → **工具** → 「互联同步」 → **配对**，填：

| 字段 | 填什么 |
|---|---|
| 服务器地址 | 你对外访问的地址，例如 `https://novara.example.com`（必须 https；仅本机回环可用 http） |
| 空间 ID | 第 1 步打印的 space id |
| 配对密钥 | 第 1 步打印的 enrollment secret |
| 空间密钥 | **首次配对留空**（第一次配对的设备会生成它） |
| 本机名称 | 随便起，用于在设备列表里认出这台机器 |

配对成功后会出现「空间密钥已保存」的提示——**这就是第二台设备加入的唯一凭据**，请妥善保存（也可随时在卡片里「导出到文件」备份）。

> 加入**已有**空间（第二台电脑）：其余字段同上，**空间密钥填"创建它的那台设备上显示的密钥"**。
> 它是用各设备自己的库密码分别包装的，服务器取不回来——所以只能从创建者设备上抄。

### 第 5 步：生成手机用的凭据

在「互联同步」卡片里：

| 凭据 | 入口 | 手机端能做什么 |
|---|---|---|
| **只读令牌** | 只读访问 → 生成 | 查看（含搜索、TOTP 动态码、复制字段） |
| **编辑凭据** | 编辑访问 → 生成 | 在上面基础上**可修改、可新建、可删除** |

- 两者的**明文都只显示一次**（服务器只存哈希，之后无法再查看），请当场复制或抄下。
- 生成时一并给你一条**完整访问链接**（形如 `https://你的域名/web/#s=<空间ID>`），可直接复制发给手机。
- 两者都能**随时作废**；编辑凭据还能单独撤销对应的「Web 编辑端」设备。

### 第 6 步：手机上打开

1. 把链接发给自己（微信/邮件/笔记都行），在手机上点开；
2. 输入**令牌**（只读令牌或编辑凭据，同一个输入框）与**你的 Novara 解锁密码**；
3. 解锁后即可浏览；拿编辑凭据进来时可以直接改数据。

> 令牌只是"门禁"，**解不开任何内容**——真正的解密靠你的解锁密码。两道锁缺一不可。

## 5. 手机端的已知限制（如实说明）

| 限制 | 说明 |
|---|---|
| **刷新就要重新解锁** | 密码与解密后的内容只存在于当前页面内存，**不写入手机的任何存储**（无 localStorage / IndexedDB / Cookie）。这是安全设计，不是缺陷 |
| **安装到主屏后从图标启动会提示"链接不完整"** | 空间标识写在链接的 `#` 片段里，而 `start_url` 无法携带片段。从浏览器书签/历史进入即可 |
| **必须 HTTPS** | 见 2.3 |
| **明文不落手机** | 复制的内容会进系统剪贴板；Novara 侧不做任何持久化 |

## 6. 出问题了怎么办

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 打开链接跳到 `127.0.0.1` | 反代没转发 `X-Forwarded-Proto/Host` | 按 `deploy/Caddyfile` 补齐；跨机反代补 `NOVARA_SYNC_TRUSTED_PROXIES` |
| 接口返回 **403 "https is required for api requests"** | 服务端看起来收到的是明文：反代没转发协议头、跨机反代未登记、或直接暴露了明文端口 | 补协议头 / 登记反代 IP / 不要把明文端口开到网络 |
| **服务端启动即退出**，提示 refusing to start | 站点目录指到了包含数据目录的位置（静态托管会把密文库暴露出去），或站点目录里有指向别处的链接（junction/符号链接） | 把站点目录指向纯站点目录，或把数据目录移出它；站点里的链接请改为把内容搬进来 |
| "当前浏览器不支持所需的加密能力" | 不是安全上下文：明文 HTTP，或自签证书未被信任 | 用 HTTPS；自签需装 CA **并开启完全信任** |
| "令牌无效或已作废" | 抄错、已重新生成或已作废 | 重新复制；`I/L→1`、`O→0` 会自动折叠，不必手工纠正 |
| "口令不正确" | 填的不是手机上的任何密码 | 是**包装空间密钥的那个 Novara 解锁密码** |
| 手机能打开但一直转圈 | 服务器关机 / 隧道断了 / 域名解析变了 | 先确认服务端进程还在，再确认通道 |
| 桌面端说「已配对」但同步不动 | 同步总开关没开 | 打开总开关；或点「立即同步」手动跑一轮 |
| 忘了空间密钥 | 只能在创建它的设备上「查看空间密钥」 | 也可以用之前导出的 `.novakey` 备份文件导入取回 |
| 某台设备丢了 | — | 在「设备中心」撤销它；撤销后该设备立即失去同步与读取，需重新配对 |

## 7. 安全边界（你应当知道的事实）

### 7.1 服务器持有什么、永不持有什么

| 项 | 服务器 |
|---|---|
| 你的数据 | 只有**密文**（AES-256-GCM）——它打不开 |
| 空间密钥的封装记录 | 持有（**被你的解锁密码加密**过；没有密码解不开） |
| 各类令牌 | 只存**哈希**（明文只在生成时给你看一次） |
| **空间密钥本身** | **永不持有**（由你的电脑生成） |
| 你的解锁密码、明文数据 | **永不接触** |

### 7.2 唯一真正薄弱的地方：你的解锁密码

拿到"封装记录 + 一个令牌"的人可以**离线**暴力破解你的解锁密码。封装用了 300 万次 PBKDF2-SHA256 迭代（约 0.3 秒/次），这个成本就是门槛。

**所以：请用一个强密码。** 它比选哪条上线路径重要得多。

### 7.3 两组"能做什么"的凭据，请分开保管

- **只读令牌泄漏** → 对方还得有你的密码才能看内容；且它只能读。
- **编辑凭据泄漏** → 对方可以**覆盖云端的密文**（可用性问题），但**依然拿不到明文**（没有密码解不开），也**无法伪造出你电脑会接受的版本**（每条数据的完整性由密钥签名保护）。

## 8. 常见问题

**Q：会不会哪天变成收费的云服务？**
不会。架构上就没有官方云：服务器是你自己的，Novara 官方没有你的数据，也没有你的密钥。自托管不是"低配版"，是设计决策。

**Q：服务器挂了/忘续费，我的数据会没吗？**
不会。你的电脑是权威副本，全部数据都在本地。服务器丢了只是"暂时不能跨设备访问"，重建一个服务器、重新配对、把电脑推一份上去就恢复了。

**Q：能给家人/朋友看吗？**
可以：把只读令牌和链接给对方即可（**但不建议把解锁密码一起给**——那样等于把你的全部数据交出去，且令牌只是门禁）。更好的做法是之后用「安全快照」导出只读副本单独分享。

**Q：能同时接几台设备？**
电脑、Web 编辑端各算一台设备，数量不受限；每台都能在「设备中心」单独撤销或重置令牌。

**Q：为什么我的手机上看不到回收站里的内容？**
这是对的：已删除（在回收站里）的数据不会出现在手机端。

**Q：能装在 NAS 上吗 / 有 Docker 吗？**
当前版本的服务端随 **Windows** 安装包提供，运行在 Windows 上。**Docker、NAS（群晖/威联通）、Linux 部署文档随下一个版本提供**——现在的四条路径都只需要一台 Windows 机器。

**Q：手机端能编辑，会不会把电脑上的改动覆盖掉？**
不会静默覆盖。两端同时改会触发冲突提示：手机端会**保留你的改动**，并让你选择"复制出来 / 导出 / 用本地版本覆盖云端"，电脑端则提供差异对比与两个版本的选择。

**Q：需要用固定 IP 吗？**
不需要。用域名（路径 A）或 Tailscale（路径 B）都可以，家里宽带 IP 变化不影响。

## 附录 A：环境变量速查（服务端）

| 变量 | 默认 | 说明 |
|---|---|---|
| `NOVARA_SYNC_DATA` | 当前目录下的 `data` | 数据目录。**不要**让它落在站点目录之内，否则服务端拒绝启动 |
| `NOVARA_SYNC_WEB_ROOT` | 服务端目录下的 `Novara.Web` | 手机端只读/编辑页面；不存在则只跑 API |
| `NOVARA_SYNC_TRUSTED_PROXIES` | 空 | 反代在**别的机器**上时填它的 IP（逗号分隔） |
| `NOVARA_SYNC_ALLOWED_HOSTS` | 空 = 不限制 | 填了就只接受这些 Host；域名固定时建议填。**只填主机名**（别带端口），否则所有请求都会被拒且启动时会告警 |
| `NOVARA_SYNC_STORE` | `sqlite` | 可选 `file`（零依赖 JSON 存储） |
| `NOVARA_SYNC_QUOTA_BYTES` | 500 MB | 单个空间的容量上限 |
| `NOVARA_SYNC_MAX_VERSIONS` | 10 | 保留的历史版本份数（冲突副本单独计数） |
| `NOVARA_SYNC_MAX_PAYLOAD_BYTES` | 64 MB | 单次上传上限 |
| `NOVARA_SYNC_MAX_AUTH_FAILURES` | 10 | 认证失败限速阈值（1 分钟窗口） |
